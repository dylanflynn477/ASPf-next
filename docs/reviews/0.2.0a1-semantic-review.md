# 0.2.0a1 adversarial semantic review

Review date: 2026-08-08

Scope: release branch `release/0.2-portfolio-ready`, after the global
declaration, visibility, seed-equality safety, n-variable research, historical
audit, portfolio demo, documentation cleanup, and `0.2.0a1` metadata changes.

This review tests the release boundary for accidental semantic expansion. A
"yes" below means the stated invariant still holds; it does not broaden the
supported language.

| # | Adversarial question | Result and evidence |
| ---: | --- | --- |
| 1 | Can undefined be mistaken for zero? | **No.** Undefined is absence of `__aspf_value/2`; zero is a concrete value atom. Partiality and the defined-zero portfolio cases exercise both states. |
| 2 | Can undefined positive inequality become true? | **No.** Inequality lowering first requires a positive value lookup, then compares the retrieved value. Undefined keys have no lookup tuple. |
| 3 | Does default negation remain failure of positive satisfaction? | **Yes.** Lowering creates a fresh helper whose body is exactly the positive comparison and default-negates that helper; it never complements the operator. Defined/false/undefined truth tables and an odd recursive loop are tested. |
| 4 | Can generic Clingo term ordering leak into numeric comparison? | **No.** Every ordered lookup requires private integer markers for both runtime operands. Scalar ordered right operands must be integer literals, and ordered value variables are rejected. |
| 5 | Are declared and undeclared functional terms interpreted correctly under `#`? | **Yes within the documented boundary.** Exact declared right signatures become application operands; undeclared ground compound terms remain Herbrand values. Global mode treats positive-arity right functional expressions as applications and uses the documented signature rule for zero arity. |
| 6 | Do declared symbols retain normal Herbrand meaning outside n-atoms? | **Yes.** Ordinary statements are preserved, and the historical ordinary-use fixtures solve with both the Herbrand atom/term and the non-Herbrand assignment. |
| 7 | Can global `#nherb.` affect ordinary predicates? | **No.** It is typed program policy consulted only while parsing operands under supported `#` connectives. Ordinary global-mode coexistence is a conformance case. |
| 8 | Can visibility directives change solver semantics? | **No.** Non-Herbrand visibility directives are omitted from lowered solver input and evaluated only while normalizing reconstructed assignments. Tests compare hidden and visible programs across models. |
| 9 | Did equality-based safety make dependent comparisons safe? | **No.** Only a positive, non-default-negated scalar seed equality supplies safety. Application equality, inequality, ordering, and default negation remain dependent and nonbinding. P4/P5-style programs are rejected. |
| 10 | Can generated predicates establish source safety? | **No.** The frontend validates source variables before lowering. Private value lookups and satisfaction helpers cannot retroactively legalize a source rule. |
| 11 | Can helpers collide with user identifiers? | **No.** Every executable identifier beginning with `__aspf_` is reserved with a location-aware diagnostic. Generated temporary variables are allocated against identifiers already present in their statement. |
| 12 | Is same-name/multiple-arity resolution exact? | **Yes.** Declarations, operands, and visibility selectors use `(name, arity)` identity, with dedicated parsing, solving, and historical cases. |
| 13 | Has any increment totalized a partial function? | **No.** The backend adds only facts/rules derived from assignments, integer markers, helper definitions, and the functionality constraint. It adds no totality or value-universe rule. |
| 14 | Has a compatibility shortcut silently changed stable-model behavior? | **No issue found in the supported subset.** Ordinary statements pass through; helper rules define positive satisfaction one way from the exact positive body; visibility is post-solve. Recursive default-negation and multiple-model regressions cover the highest-risk transformation. |
| 15 | Is `_V` genuinely distinct from an ordinary Clingo variable? | **Not implemented, by design.** The research gate concluded NO-GO for the relational backend because historical n-variables are grounder-inert while an ordinary-variable rewrite grounds over candidate values. The strict xfail remains. |
| 16 | Are historical claims executable? | **Yes.** `tests/historical_compat/manifest.json` ties each claim to a fixture, expected models or diagnostic, sources, and compatibility classification; the report is generated from that manifest. |
| 17 | Are remaining xfails honest? | **Yes.** The four xfails are arithmetic, aggregate n-atoms, choice n-atoms, and n-variables. Each fixture first asserts the precise location-aware unsupported diagnostic, so unrelated failures cannot pass as expected. |
| 18 | Is the portfolio demo semantically accurate? | **Yes.** Its 14-observation values are coherent precomputed integers; the source and guide distinguish undefined from defined zero and default-negated threshold failure from an undefinedness test. It makes no trading or predictive claim. |
| 19 | Can an ASP researcher immediately find a false README claim? | **No false semantic claim found.** The README labels the project experimental, describes the reference backend and restrictions, separates Flingo, avoids full-compatibility and efficiency claims, and now states compatibility counts with subset relationships explicitly. |
| 20 | Can a general software engineer understand the purpose? | **Yes.** The README contrasts imperative programming, ASP, and ASP{f}; explains why partial values matter; shows `undefined != 0`; and provides a runnable first command before architecture details. |

## Gate outcome

**PASS for the documented `0.2.0a1` reference-backend boundary.** No new
language feature was added during this review. The next recommended technical
milestone remains a separate native-backend feasibility prototype for
grounder-inert n-variables, not arithmetic or aggregate expansion.
