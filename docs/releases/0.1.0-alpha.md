# ASPf-next 0.1.0-alpha

## Purpose

ASPf-next is an experimental, independent clean-room modernization of Marcello
Balduccini's ASP{f} language. This first alpha provides a narrow compatibility
frontend for modern Clingo 5.8 and an inspectable reference translation. It is
research software, not a complete ASP{f} implementation or native solver
extension.

## Implemented

- `#nherb f/n.` declarations;
- ground `#=` assignments in facts and complete rule heads;
- positive ground `#=` comparisons in rule bodies;
- integer, symbolic constant, and string values;
- ordinary Clingo pass-through outside supported ASP{f} syntax;
- partiality, functionality, model enumeration, human output, JSON output, and
  lowered-source inspection; and
- filename-, line-, and column-aware diagnostics for deferred constructs.

## Install

Python package version `0.1.0a1` corresponds to this release name.

```console
python -m venv .venv
# macOS/Linux: source .venv/bin/activate
# Windows:     .venv\Scripts\activate
python -m pip install -e ".[dev]"
```

## Example

```asp
#nherb balance/1.
balance(account1) #= 500.
```

```console
aspf examples/01_basic_assignment.aspf
```

The normalized model includes `balance(account1)#=500`.

## Known limitations

This alpha does not implement `#!=` or inequalities, default-negated n-atoms,
arithmetic or variables inside n-atoms, aggregates containing n-atoms, compound
assignment values, optimization, theory atoms, or a custom propagator. The
reference backend does not claim historical Clingo{f}'s grounding efficiency,
and the project does not claim full historical compatibility.

## Clean-room and attribution

Marcello Balduccini created ASP{f} and the historical Clingo{f}
implementation. Dylan Flynn created ASPf-next as an independent modernization
using public research and Clingo's supported Python API. ASPf-next does not copy
historical Clingo{f} code and is not endorsed by or affiliated with Balduccini,
the historical project, or Potassco.

## Direction for 0.2

Potential 0.2 work includes specification-backed investigation of `#!=`, broader
conformance tests, and stronger historical-specification traceability. These
items remain proposals until their semantics and tests are reviewed.
